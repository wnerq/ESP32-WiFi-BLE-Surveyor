Serial STATUS Diagnostic Line←

This card groups information or controls related to Serial STATUS Diagnostic Line. Use it to understand or operate this part of the surveyor.
Developer view exposes additional implementation and diagnostic detail for this card.

Developer view reference for the compact periodic diagnostic line and serial receive echo.

FieldMeaning
STATUSPeriodic or requested compact diagnostic snapshot.
upDevice uptime in milliseconds from millis().
wifiScanWi-Fi scan active: 1 = scanning, 0 = idle.
bleScanBluetooth scan active: 1 = scanning, 0 = idle.
wifiObsRetained Wi-Fi observations / configured Wi-Fi retention limit.
bleObsRetained Bluetooth observations / configured Bluetooth retention limit. 0/0 normally means BLE surveying is disabled.
bleScansBluetooth scan counter since this boot/session.
staInfrastructure Wi-Fi station state: 1 = connected, 0 = not connected.
loopGapLastMost recently measured interval between main-loop service entries, in milliseconds.
loopGapMaxLargest measured main-loop service gap since startup or the last diagnostic reset, in milliseconds.
heapCurrent total free heap, in bytes.
minMinimum free heap observed since boot, in bytes.
largestCurrent largest contiguous free heap block, in bytes; useful for spotting fragmentation even when total free heap is adequate.
[RX]Echo of a command received by the serial command interface. Password-bearing commands are sanitized before echo.
diag offSerial command that disables diagnostic streaming; seeing [RX] diag off records that this command was received.

Example: STATUS up=34947644 wifiScan=0 bleScan=0 wifiObs=2220/2220 bleObs=0/0 bleScans=0 sta=1 loopGapLast=6 loopGapMax=166 heap=62248 min=48568 largest=47092

Survey Status & Controls←

Shows whether surveying is active, when the last scan ran, and the controls that affect scan timing. Use it to confirm the survey is actually collecting data.
Scan state and counters are live scheduler indicators. Interval changes affect future automatic starts; Live Updates only refresh the browser.

Use this card to confirm that scanning is active, see when the last scan completed, change the automatic scan interval, and request a manual scan. Live Updates refresh the browser display; they do not trigger radio scans.

History←

Shows how much survey data is retained and how far back it reaches. Older observations roll out as the buffer fills.
Capacity reflects compact observations plus supporting identity and scan metadata; retained time depends on scan interval and observations per scan.

History is the rolling RAM record used by the web interface and CSV export. When the buffer fills, older observations age out as new observations arrive. The retained time window therefore depends on scan rate and how many observations each scan produces.

RSSI History←

Plots retained signal strength for one selected network or device. Hover over a point to see details for that observation.
RSSI is shown in dBm on a fixed scale so plots are comparable. Each point represents one retained scan observation.

RSSI is received signal strength in dBm. Values closer to zero are stronger. Select an entry in Observed Networks or Observed Devices to plot its retained observations, then hover over a graph point to see scan and signal details.

Observed Networks←

Lists Wi-Fi access points currently represented in retained history. Select a network to inspect its RSSI history.
Rows are grouped by BSSID, not SSID, so multiple radios advertising the same network name remain distinct.

This table summarizes retained Wi-Fi access points. Access points are distinguished by BSSID, so several radios can share one SSID and still appear separately. Select a network to redraw RSSI History.

Observed Devices←

Lists Bluetooth devices currently represented in retained history. Select a device to inspect its RSSI history.
Bluetooth addresses may be public, static-random, or private; address type affects how useful identity and vendor interpretation can be.

This table summarizes retained Bluetooth devices. Bluetooth addresses can change or be private, so an address is not always a permanent device identity. Select a device to redraw RSSI History.

Observed Channel Interference←

Summarizes the Wi-Fi activity seen across 2.4 GHz channels and suggests a less-congested channel.
The estimate weights observed RSSI plus co-channel and adjacent-channel overlap; it is not an airtime-utilization or noise-floor measurement.

This card estimates 2.4 GHz Wi-Fi interference from the access points seen in the latest scan. It considers signal strength and channel overlap; it does not measure actual airtime use, noise floor, or non-Wi-Fi interference.

Infrastructure Wi-Fi←

Shows the network connection used to reach the surveyor through your existing Wi-Fi. Surveying can continue even when this connection is unavailable.
Use RSSI, channel, BSSID, and reconnect diagnostics to separate infrastructure connectivity from survey-radio behavior.

This is the network connection used to reach the surveyor through an existing Wi-Fi network. Survey collection is designed to continue even if infrastructure connectivity is unavailable.

Survey Health←

Summarizes whether automatic surveying and its supporting checks are operating normally.
Warnings identify timing, allocation, or integrity conditions that merit investigation without necessarily stopping the survey.

Health checks summarize scan cadence, history integrity, and related operating conditions. PASS means the check is currently satisfactory; WARN identifies a nonfatal condition worth reviewing.

Survey Scheduler Diagnostics←

Shows detailed timing and retry information for automatic scan scheduling.
Use these counters to distinguish scan-start failures, completion failures, interaction deferral, and retry-backoff behavior.

Developer information separates scan starts, completions, retries, and request deferrals. Use it to determine whether a problem is in scheduling, scan startup, or scan completion.

CSV Diagnostics←

Shows how often survey CSV files have been exported and how the most recent export performed.
Useful for spotting long-running exports or response delays when history is near capacity.

Shows CSV export counts and recent export performance. This is useful when testing responsiveness with a large retained history or simultaneous browser activity.

Wi-Fi Memory Diagnostics←

Shows Wi-Fi history table sizes, identity usage, and heap margin.
Watch free heap, largest block, AP-table utilization, and history-integrity checks when stress testing near capacity.

Shows compact-history allocation, AP identity-table use, metadata use, heap margin, and history-integrity checks. Near-capacity tests should remain responsive without corrupting retained references.

BLE Implementation Diagnostics←

Shows Bluetooth history-table usage and memory pressure.
Use address/metadata utilization and heap metrics to evaluate dual-radio allocation pressure.

Shows Bluetooth address-table, scan-metadata, history, and heap usage. These values are especially useful when Bluetooth and Wi-Fi surveying run together and share limited RAM.

Device←

Identifies the running firmware, hardware, build, and uptime. This is the first place to confirm what device and software you are looking at.
Firmware/core/IDF and reset information are useful when reproducing behavior across builds or boards.

Identifies the running firmware and hardware, build time, uptime, and reset reason. Record this information when comparing devices or reporting a problem.

System Health←

This card groups information or controls related to System Health. Use it to understand or operate this part of the surveyor.
Developer view exposes additional implementation and diagnostic detail for this card.

A quick summary of the device state. Use Standard view for the result and deeper views for the individual checks behind a warning.

Memory←

Shows available working memory and the lowest memory margin seen since startup. Low memory can reduce responsiveness or prevent operations from completing.
Minimum free heap shows peak pressure; largest free block helps distinguish total free memory from fragmentation.

Free heap is working memory available now. Minimum free heap is the lowest margin seen since startup. Largest free block helps show whether free memory is fragmented into pieces too small for a large allocation.

Network←

Shows how the device is connected and the addresses used to reach its web interface.
Use interface mode, MACs, channel, reconnect count, AP state, and mDNS state when diagnosing connectivity.

Shows infrastructure connection state, the surveyor's own access point, mDNS address, MAC addresses, channel, and reconnect information used to diagnose how the web interface is being reached.

Diagnostics Export←

This card groups information or controls related to Diagnostics Export. Use it to understand or operate this part of the surveyor.
Developer view exposes additional implementation and diagnostic detail for this card.

Downloads a JSON snapshot of System information, survey state, configuration, boot memory checkpoints, and recent bounded diagnostic events. It is intended to make troubleshooting snapshots portable.

Restart Device←

This card groups information or controls related to Restart Device. Use it to understand or operate this part of the surveyor.
Developer view exposes additional implementation and diagnostic detail for this card.

A normal System restart first tries to preserve current survey history. If preservation fails, the device does not restart until you explicitly confirm that the current Wi-Fi and Bluetooth history can be erased.

Boot Heap Checkpoints←

Shows memory at major startup stages so you can see where RAM is consumed.
Compare free heap, minimum heap, and largest block across initialization stages to isolate subsystem costs.

Developer startup measurements show how free heap, minimum heap, and the largest contiguous block change as major subsystems initialize.

Session←

Shows whether survey history was restored through a controlled restart and the current restart-preservation status.
Restart checkpoints are temporary continuity data and are deleted after successful restore.

Restart checkpoints temporarily preserve the current RAM survey through intentional restarts. A successfully restored checkpoint file is deleted so it is not repeatedly restored on later boots.

History Test Tools←

Developer-only controls fill history with synthetic observations for near-capacity UI and rollover testing.
Synthetic data exercises compact history/table behavior but is not a substitute for radio or endurance testing.

Developer prefill creates synthetic history at selected capacity targets for UI, rollover, and performance testing. Synthetic entries are not evidence of radio endurance or RF behavior.

Infrastructure Network←

Configures the existing Wi-Fi network the surveyor can join for browser access.
Credentials are stored separately and are intentionally excluded from configuration export.

Scan for nearby Wi-Fi networks and select one to fill the SSID field, or enter an SSID manually for hidden or currently unseen networks. Credentials are saved only after a successful connection, and passwords are intentionally excluded from configuration backup files.

Device Identity←

Configures the friendly local hostname used to reach the surveyor on networks that support mDNS.
Changing the hostname requires restart because mDNS advertisement is initialized at boot.

The mDNS hostname provides a friendly local address where supported. The default is surveyor.local; use a unique hostname when multiple surveyors share a LAN. A hostname change requires restart so the new identity can be advertised from startup.

Device AP←

Configures the surveyor's own Wi-Fi access point, which provides direct browser access when infrastructure Wi-Fi is unavailable.
Changing AP state, SSID, or password requires restart and can affect how you reconnect to the device.

The surveyor can provide its own Wi-Fi access point for direct browser access. Changing AP state, SSID, or password can require reconnecting to the device after restart.

Survey Mode←

This card groups information or controls related to Survey Mode. Use it to understand or operate this part of the surveyor.
Developer view exposes additional implementation and diagnostic detail for this card.

Bluetooth surveying can be enabled or disabled. Bluetooth consumes additional RAM, so changing this mode requires restart and changes how survey-history memory is divided.

Wi-Fi Capture←

This card groups information or controls related to Wi-Fi Capture. Use it to understand or operate this part of the surveyor.
Developer view exposes additional implementation and diagnostic detail for this card.

Hidden networks are always detectable for RF/channel analysis. When hidden-history capture is disabled, future hidden observations do not consume AP-table or retained-history capacity; existing hidden history ages out normally.

Interface & Indicators←

Controls device indicators and explains browser-local display choices.
Theme and View are browser-local; status LED state is stored on the surveyor.

Status LED behavior is stored on the device. Theme and View are browser-local display choices, so different browsers can use different presentation preferences.

Configuration Backup & Restore←

Exports and restores non-secret device settings so a configuration can be reproduced without re-entering every option.
Import validates the complete schema before writing settings; credential fields are intentionally excluded.

Configuration export contains the device's non-secret configurable settings. Import validates the complete supported schema before writing settings. Wi-Fi and AP passwords are intentionally excluded.
